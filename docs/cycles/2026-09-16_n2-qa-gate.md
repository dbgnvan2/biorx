Binary: REJECTED. The refactor itself is sound — the recovery chain was moved
faithfully, both front ends call it, the two named defects are fixed, and the
notice heuristic is correctly gated. But the change routes an existing summary

`web.routes_summaries.recover_abstract`, or drop the DOI so recovery no-ops).

## Verification by construction (caller checklist a–f)

### (a) recover_abstract against the live services — PASS

Ran `recover_abstract` directly, timed:

- DOI-only `10.1038/s41586-020-2649-2` → found via `europepmc`, 1326 chars,
  1.91 s, `tried=['europepmc']` (stopped at step 1).
- PMCID-only `PMC13572605` → found via `pmc_fulltext`, 1978 chars, 13.28 s —
  the PMC step now runs with no DOI (the fix).
- PMC-link-only `best_oa_url=…/PMC13572605/` → found via `pmc_fulltext`, 1978
  chars, 9.90 s — `pmcid_of` extracts the id from the link.
- nothing (`{"title": "only a title"}`) → not found, `tried=[]`, 0.00 s, zero
  network calls.

Each case that found text stopped at the first success and did not fan out to
later sources.

### (b) A failing/slow source must not hide another — PASS, no unbounded wait

- A raising source is caught by the `attempt()` wrapper and logged; the chain
  continues (confirmed by `test_n2_a_source_that_raises_does_not_stop_the_chain`,
  which passes).
- Every source has a bounded timeout: Europe PMC `get_by_id` 30 s, PMC full-text
  20 s, Crossref 15 s, OpenAlex 15 s, scrape 20 s. No retry loop, no `while`,
  no recursion — nothing can hang indefinitely.
- Worst case is ~100 s of *sequential* bounded latency, but it runs inside a
  background job (web) / `QThread` (GUI), never blocking a request or the UI.

### (c) P12 — old worker vs new `recover_abstract`, step by step — PASS

Diffed `git show origin/main:gui.py` (`AbstractFetchWorker.run`) against the new
`src/paper_meta.recover_abstract`:

- Step 1 Europe PMC by DOI: identical (get_by_id → abstractText; a revealed
  `pmcid` feeds step 2 in both).
- Step 2 PMC full-text: new one runs on `pmcid` from record OR DOI lookup OR a
  PMC link; old one ran only under `if self.doi` (defect #1) and only from
  `self.pmcid`/lookup. Fix, not a drop.
- Steps 3–4 Crossref/OpenAlex: identical, gated on `doi` in both.
- Step 5 scrape: old scraped `source_url` + `doi.org/doi`; new scrapes
  `best_oa_url` + `source_url` + `url` + `doi.org/doi`. The old worker silently
  skipped the open-access link (defect #2); new one adds it. No dropped target.
- Failure signalling: old emitted the sentinel string `"(Abstract not available
  from any source)"` on the *success* channel (P14 — the defect this commit
  fixes); new returns `AbstractRecovery(found=False, text="")` and the GUI worker
  maps that to a display-only message. The worker's `except → error` path is
  retained, now only for unexpected escapes (sources are swallowed+logged).

No former side effect was lost. The two behavioural changes are the two fixes
the commit names, plus the scrape target set widening to the open-access link.

### (d) Notice-title heuristic — PASS

`non_article_kind` is only reached when `not abstract and not full_text` AND
recovery returned nothing, so a real article with text (record abstract, PDF
text, or a recovered abstract) can never be refused by it — verified by code
path and by `test_n2_recovery_is_not_attempted_when_the_record_has_an_abstract`.
Matching is `startswith` (prefix), not `in` (contains); the mutation `startswith
→ in` turned `test_n2_notice_titles_are_recognised_from_the_shipped_config` red
on `"A study of retraction rates"` (would wrongly match `retraction`), so the
guard is pinned and provable-failing. Minor cosmetic issue: `f"{prefix.rstrip(':')}
notice"` yields slightly awkward English for multi-word prefixes ("a expression
of concern notice") — not a correctness defect.

### (e) A recovered abstract that is error text / a page tagline — LOW (F3)

`recover_abstract` itself has no minimum-length floor: `found` is `bool(text)`,
and `attempt()` accepts any non-empty stripped string. In practice the risk is
confined to the scrape path, which already enforces `MIN_ABSTRACT_CHARS=80` and
`MIN_HTML_CHARS=500` (a short tagline or an error/interstitial page is rejected
there). The structured sources (Europe PMC `abstractText`, PMC JATS `<abstract>`,
Crossref `abstract`, OpenAlex reconstructed index) return trusted content, so
error text cannot plausibly originate from them. Residual gap: a *long* (>80-char)
journal tagline served as `meta description` on a page whose structured sources
all miss would still be captured and stored/summarized — a pre-existing heuristic
limit of `scrape_abstract_from_url` (extracted verbatim), not introduced by N2.

## FINDINGS

F1 · P5/P34 · tests/web/test_summaries_routes.py::test_a_paper_with_no_text_at_all_is_an_error · HIGH (blocking)
  The N2 change inserted `recover_abstract` into `_run_summary`, and this
  pre-existing test — which posts `{**PAPER, "abstract": ""}` with the fake DOI
  `10.1234/agents` — does **not** stub it (it only patches
  `src.llm_providers.build_client`). The job therefore makes real HTTP calls to
  Europe PMC, Crossref, OpenAlex, and `doi.org/10.1234/agents` and races the 5 s
  `_await` timeout. First full-suite run: exit 1, job phase "Looking for the
  abstract", error `(looked in: europepmc, crossref, openalex, scrape)`. Re-run:
  exit 0 (485 passed). Every *new* N2 test stubs `recover_abstract`; this sibling
  was not updated — the exact P5 "harden all sibling calls" miss, and a P34-style
  leak of the real network into the suite. Fix: stub
  `web.routes_summaries.recover_abstract` in the test (return
  `AbstractRecovery("", None, ["europepmc"])`), or remove the fake DOI so the
  recovery chain makes no calls. Re-sweep after fixing.

F2 · P21/P25 · tests/test_n2_abstract_recovery.py::test_n2_gui_worker_and_web_route_use_the_same_recovery · LOW
  The plan calls for an "identity check, as for filter_papers", but the test only
  patches `gui.recover_abstract` and asserts the worker calls it — it never
  asserts `gui.recover_abstract is src.paper_meta.recover_abstract`. If someone
  swapped the GUI to its own implementation, the test would stay green. The
  wiring is currently correct (both import from `src.paper_meta`), so this is a
  test-quality gap, not a live defect. Recommend adding the identity assertion
  (`assert gui.recover_abstract is paper_meta.recover_abstract`).

F3 · P14 · src/paper_meta.py::recover_abstract · LOW
  No central minimum-length guard on recovered text; `found` is `bool(text)`.
  Structured sources return trusted content, and the scrape path guards itself
  (see (e)), so a recovered abstract is not *in practice* error text or a short
  tagline. Consider a shared floor (e.g. `MIN_ABSTRACT_CHARS`) applied to the
  scrape result only, or a comment stating why the structured sources are trusted
  unguarded. Not blocking.

## Verification by construction (fix-loop checklist a–e)

### (a) Determinism — PASS

Five back-to-back full-suite runs, all exit 0: 498 passed, 16 skipped
(6.98 s, 6.74 s, 6.73 s, 6.73 s, 6.73 s). The suite that flaked in the N2 gate
(exit 1 then 0) is now stable, and the whole run is ~7 s — the flaky test no
longer spends 5 s racing a live Europe PMC lookup.

### (b) Trying to defeat the guard — coverage, stated plainly

Probed each vector against the real guard in an inner pytest session
(`tests/conftest.py` copied into a scratch dir). Covered = the attempt FAILS
(or is caught at teardown); missed = the attempt PASSES cleanly.

COVERED (the test fails / errors):
- `socket.create_connection(("example.org", 80))` — failed (getaddrinfo + connect).
- IP literal `192.0.2.1` / `93.184.216.34` — failed.
- IPv6 global literal `2001:db8::1` / `2606:2800:…` — failed (both connect and getaddrinfo).
- `requests.get(...)` swallowing the exception — passed, then ERROR at teardown
  (`this test tried to reach the network …`).
- `urllib.request.urlopen(...)` swallowing — same teardown ERROR.
- A bare swallowed `socket.getaddrinfo("api.openalex.org", 443)` — same teardown ERROR.

NOT COVERED (the test passes cleanly — inherent monkeypatch limits):
- A subprocess: a child interpreter has its own unpatched `socket`; the guard does
  not reach it. Proven (`SUBPROCESS_REACHED_NETWORK` printed, parent test green).
- Import-time capture: a module that does `from socket import getaddrinfo` (or
  caches `socket.socket.connect`) at import time — i.e. during collection, before
  the session fixture patches — holds the unpatched reference. Proven
  (`CAPTURED_REF_BYPASSES_GUARD`).
- A library with its own resolver (dnspython, aiohttp's C resolver): not
  installed and not used anywhere in this repo, so untestable here; would bypass
  by construction if introduced.

Assessment: all three gaps are intrinsic to any in-process socket monkeypatch and
none is reachable by this codebase, whose only network paths are `requests`
(urllib3 → call-time `socket.getaddrinfo`/`connect`) — the exact thing the guard
covers and the probes proved. The guard caught precisely the one test the N2 gate
found, and nothing else, when it was switched on.

### (c) The guard does not break legitimate local use — PASS

Full green suite includes: every TestClient web test (in-process ASGI, no socket),
SQLite (`tests/test_db_concurrency.py` 38 passed), the node subprocess test
(`test_safeurl_behaviour`, 12 parametrized runs against real node v26.8.2),
the `git` subprocess tests (`test_no_retrieval_drift.py`), the `sh -c` subprocess
tests (`test_deploy_files.py`), and the guard's own loopback inner test. Loopback
(`127.0.0.1`, `::1`, `localhost`) and Unix-domain sockets are whitelisted by
`_LOCAL_HOSTS`; subprocesses are untouched by the in-process patch, so git/node/sh
keep working.

### (d) Minimum-length floor and the `_OUR_BUGS` split — PASS

Floor: `MIN_ABSTRACT_CHARS = 80` is now applied to every source in `attempt()`,
not just the scraper. A genuine abstract is never that short — the real PMC
fixture is 1978 chars, the live Europe PMC hit was 1326 chars, and 80 chars is
~11–14 words. Rejecting a sub-80 string degrades to the existing "no abstract"
message; it cannot crash. One cosmetic inconsistency (non-blocking): the scraper
uses `> MIN_ABSTRACT_CHARS` (strict) while the new central check is
`< MIN_ABSTRACT_CHARS`, so an exactly-80-char string would pass the central floor
but is never produced by the scraper — no effect in practice.

`_OUR_BUGS` split: `NameError/TypeError/AttributeError/ImportError/SyntaxError`
now log at ERROR with `exc_info=True` and still `return False` — the chain
continues, it does not crash. Real service failures (`ConnectionError`,
`requests.*`, `Timeout`) are not in the tuple, so they stay at INFO and continue,
and remain visible in `result.tried`. Neither branch hides a failure: a service
failure is logged and recorded; a programming error is loud. Covered by
`test_n2_a_programming_error_in_a_source_is_logged_loudly` and
`test_n2_a_network_failure_in_a_source_stays_quiet`.

### (e) The new tests can fail — PASS (by mutation)

- Removed the teardown `pytest.fail` → `test_a_swallowed_network_attempt_still_fails_the_test`
  FAILS (`{'errors': 0} != {'errors': 1}`).
- Disabled the floor (`len(text) < 0`) → all five
  `test_n2_a_too_short_result_is_not_accepted_as_an_abstract` cases FAIL.
- Removed the `_OUR_BUGS` clause → `test_n2_a_programming_error_in_a_source_is_logged_loudly`
  FAILS (NameError logged at INFO, not ERROR), while the network-quiet test stays green.
- F2 identity assertions are `is` comparisons of two live imports
  (`gui.py:222-223` and `web/routes_summaries.py:23` both `from src.paper_meta import
  recover_abstract`); a copy in either front end makes `is` False → red. Non-vacuous

All three mutations reverted; `git diff` clean (only the pre-existing untracked
`Social Baseline Theory.xlsx`, this gate file, and `docs/spec_make_it_great.md`).

## Findings (fix-loop 1)

None blocking. Two observations carried forward, neither a gate item:

- The guard does not observe subprocesses, import-time-captured socket references,
  or third-party resolvers (dnspython/aiohttp). Acceptable for this repo today;
  if a future dependency starts resolving DNS through its own path, the guard must
  be revisited. Worth a one-line note in `tests/conftest.py`'s docstring.
- `_OUR_BUGS` includes `SyntaxError`, which is almost never raised at runtime
  (compile-time), and `ImportError` (whose subclass `ModuleNotFoundError` would
  turn a missing optional dependency into an ERROR log). Both are safe — they only
  make things louder — but the tuple's intent (our defect, not the service's) is
  slightly broader than the name suggests.
