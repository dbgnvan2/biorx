## Deviations from the plan

- **M5:** `/api/session/lookup` still returns `pin_set`; it adds
  `setup_code_required`. After a PIN reset the access code alone cannot set a
  new PIN, which was the risk the plan named.
- **M7:** `/healthz` returns `{"ok": true}`. What the sign-in page needs
  (`access_code_set`, `pin_min_length`, `codes_in_use`, `startup_warnings`) is
  on public `/api/gate`; everything else is on authenticated `/api/config`.
  The plan put it under `/api/me`.
- **A5:** keys stored in the browser before scoping are dropped rather than
  migrated (they cannot be tied to an account safely); the user re-enters one.
- **M11:** the query bound is 9 statements, not 5: ids are chunked to stay
  under SQLite's parameter limit.
- **M34:** `src/selection.py` stays because `gui.py` (retiring) imports it.
  `upsert_filter` was deleted too (nothing but tests called it once saves refused taken names).
- **T2:** the 2026-09-15 schema has no `login_name`; the case-duplicate test
  adds that column without its unique index, which is the state that crashed.
